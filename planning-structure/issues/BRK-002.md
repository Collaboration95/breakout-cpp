## Objective

Make the application behave like a live window: it processes events, renders
continuously at the documented dimensions, and exits promptly through normal
window-close or Escape input.

## Value / context

The current scaffold processes events before drawing and delays after the event
loop. Every later feature depends on a stable frame loop with a clear ownership
of event processing, update timing, and presentation.

## In scope

- The documented 864×558 application window.
- A continuous clear/present cycle while the application is running.
- Window-close and Escape exit behavior.
- Removal of post-exit waits or other behavior that makes the process appear
  hung after the user closes it.

## Out of scope

- RAII/resource ownership; that is BRK-003.
- Gameplay updates, fixed timestep physics, text, or background assets.
- Frame-rate optimization beyond keeping the loop responsive.

## Requirements

- The window remains responsive while idle.
- Every active loop iteration presents a current frame.
- Close and Escape request the same application shutdown outcome.
- The application does not continue sleeping or waiting after shutdown has been
  requested.

## Acceptance criteria

- A manual run shows a responsive 864×558 window for at least a short idle
  period.
- Escape closes the application without requiring a second input.
- The window close control closes the application without a crash.
- No drawing occurs only after the event loop has already ended.

## Verification

- Run once and leave the window idle.
- Close it with Escape and repeat with the window close control.
- Observe the process exit and confirm there is no unexplained delay.

## Dependencies

BRK-001.

## Risks and decisions

Do not solve timing for gameplay in this issue. The only timing requirement here
is a responsive loop; simulation cadence is deliberately deferred to BRK-007.

## Stop conditions / escalation

Stop if event processing and rendering ownership cannot be separated without
changing the intended application lifetime. Record the conflict for review.
