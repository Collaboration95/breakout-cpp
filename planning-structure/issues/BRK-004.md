## Objective

Create a small rendering boundary that can clear, present, and draw basic
rectangular game geometry without making the game model responsible for SDL
state management.

## Value / context

The simulation should be readable independently from the drawing calls. A thin
boundary now makes later physics and pure logic checks easier without forcing a
large final architecture.

## In scope

- Clearing and presenting the current frame.
- Drawing solid rectangles with the documented coordinate system.
- A visible smoke-test shape at a known location.
- The boundary between native renderer ownership and callers that request draw
  operations.

## Out of scope

- Textures, fonts, audio, or buttons.
- Paddle movement or collision logic.
- A texture cache or generalized scene graph.

## Requirements

- Basic geometry is drawn at the expected pixel coordinates.
- Callers do not need to destroy or reinitialize the renderer.
- Rendering failure behavior is observable enough to diagnose during development.
- The existing continuous loop remains responsive.

## Acceptance criteria

- A solid rectangle can be displayed in a manual run at a known location.
- Clear and present happen once per active frame in a coherent order.
- The rendering boundary does not expose a second competing ownership path.

## Verification

- Run the application and visually confirm the smoke-test rectangle.
- Resize or alter the known rectangle temporarily only if needed to confirm the
  coordinate convention; restore the intended baseline afterward.
- Re-run the foundation close checks.

## Dependencies

BRK-003.

## Risks and decisions

Avoid designing a general-purpose rendering engine. The issue is complete when
the game can request the few operations needed by the next object issue.

## Stop conditions / escalation

Stop if SDL ownership starts leaking into game objects or if the renderer
boundary requires decisions about textures/fonts that belong to later issues.
