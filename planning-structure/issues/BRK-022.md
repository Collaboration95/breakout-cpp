## Objective

Connect the save-slot model, file persistence, name entry, and screen state into
the documented three-slot user flows.

## Value / context

This is the user-facing persistence milestone: a short weekly coding session can
now be resumed by saving the game and loading it later.

## In scope

- Load-game screen with three slots and their status.
- Empty-slot naming before starting or saving where the reference requires it.
- Saving an active round to a selected slot.
- Quitting and relaunching, then loading a slot.
- Reset-save-file behavior.
- Selected-slot and quick-game semantics.

## Out of scope

- High-score recording.
- Audio transitions.
- Redesigning the slot file format after BRK-020 has been decided.

## Requirements

- Slot identity is stored as data and is not recovered by parsing display text.
- Empty, saved, and lost slots take the documented routes.
- A saved round resumes with its score, ball/paddle state, and brick health.
- Reset returns all slots to the chosen default state and persists that result.
- A save/load failure is visible and does not silently start the wrong slot.

## Acceptance criteria

- A user can name an empty slot, start or save a game, quit, relaunch, and load
  that slot.
- Loading a slot shows the expected progress rather than a fresh round.
- Resetting the save file removes prior slot progress after relaunch.
- Quick Game does not accidentally overwrite a selected save slot.

## Verification

- Exercise all three slots, including one empty and one previously used slot.
- Relaunch between save and load.
- Test reset followed by relaunch and inspect every slot.

## Dependencies

BRK-020, BRK-021, and BRK-018.

## Risks and decisions

Keep slot-flow behavior separate from high-score recording. If the reference
docs or chosen save format leave a route ambiguous, record it before coding.

## Stop conditions / escalation

Stop if save/load requires changing the core simulation state contract or if a
malformed slot can select a different slot. Escalate the data-boundary issue.
