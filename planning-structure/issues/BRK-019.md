## Objective

Define the in-memory game-state and three-slot model needed for fresh, active,
saved, lost, and continued games without shallow ownership of player names or
other dynamic data.

## Value / context

The original C state copies heap pointers and relies on careful `strdup`/`free`
discipline. C++ value semantics should make copying a saved game understandable
and safe before disk serialization is added.

## In scope

- Active game state and three save-slot states.
- Explicit status values and selected-slot meaning.
- Copy/move behavior for names, geometry, score, and brick health.
- Fresh/continue/load decision rules as in-memory behavior.
- Resetting a slot to a known empty/lost/default state.

## Out of scope

- File parsing or writing.
- Name-entry UI.
- High-score entries and audio.

## Requirements

- Copying a state does not create shared mutable ownership for the name or
  equivalent dynamic fields.
- A fresh game, a continued active game, and a selected saved slot are
  distinguishable.
- Slot status transitions are explicit and testable without SDL rendering.
- A reset slot cannot retain stale brick health or score.

## Acceptance criteria

- Focused checks cover fresh, continue, load, and reset decisions.
- Mutating a copied state does not mutate its source.
- The three slots can coexist with independent names and game data.
- The model can report enough state for the later screens to render it.

## Verification

- Create and copy several states, then mutate source and copy separately.
- Exercise each decision path with empty, active, saved, and lost statuses.
- Run the existing core game smoke test afterward.

## Dependencies

BRK-012.

## Risks and decisions

Do not preserve `temp_collision` merely because it exists in the old file if it
has no behavioral meaning. Record compatibility requirements before removing
any persisted field.

## Stop conditions / escalation

Stop if a state-copy test reveals unclear ownership or if a save-file format
decision is required to define the in-memory model.
