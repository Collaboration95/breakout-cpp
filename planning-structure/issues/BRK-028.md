## Objective

Persist the automatic-mode setting and provide the documented settings-screen
toggle and save-reset behavior.

## Value / context

Settings are a small independent persistence path and a useful test of whether
the screen can reflect model state without changing a button label as a hidden
source of truth.

## In scope

- Settings file location and one boolean setting.
- Loading defaults and saving changes.
- Settings screen presentation and toggle behavior.
- Reset-save-file action from settings.
- Returning to the main menu after settings work.

## Out of scope

- Automatic paddle movement itself; BRK-029 owns it.
- Volume controls or a general configuration framework.
- Reworking save-slot serialization.

## Requirements

- Missing or malformed settings follow an explicit default policy.
- Toggling updates actual settings state and redraws from that state.
- Relaunching preserves a successful setting change.
- Reset-save-file affects the save slots without silently changing unrelated
  settings unless deliberately chosen.

## Acceptance criteria

- A user can toggle automatic mode in the settings screen.
- The setting survives relaunch.
- Reset-save-file produces the documented slot result.
- Changing presentation text cannot invert the underlying setting accidentally.

## Verification

- Toggle on, relaunch, and inspect the setting.
- Toggle off, relaunch, and inspect again.
- Reset save data and verify slots separately from the setting.

## Dependencies

BRK-022 and BRK-018.

## Risks and decisions

Keep settings persistence separate from the save-slot file unless the decision
ledger explicitly chooses a combined format.

## Stop conditions / escalation

Stop if reset behavior cannot distinguish settings data from save-slot data.
