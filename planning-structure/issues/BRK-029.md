## Objective

Make the settings-driven automatic mode move the paddle in response to the ball
while preserving the field boundaries and chosen round lifecycle.

## Value / context

Auto-play completes the original feature set, but the C version contains a dead
clamp that can move the paddle off-screen. This issue isolates that behavior and
forces a deliberate fidelity choice.

## In scope

- Enabling/disabling automatic paddle control from settings.
- Ball-following behavior during an active round.
- Paddle boundary enforcement.
- Interaction with manual input and round reset.

## Out of scope

- New AI difficulty levels.
- Settings-file parsing.
- Audio behavior.

## Requirements

- Automatic mode is inactive when the setting is off.
- When active, the paddle follows the chosen ball target according to a clear
  policy.
- The paddle remains within the documented playable range unless an explicit
  compatibility decision preserves the original bug.
- Automatic mode does not bypass game-over or reset state transitions.

## Acceptance criteria

- The setting visibly changes paddle behavior during a round.
- The paddle does not leave the field under normal automatic play unless that
  behavior is explicitly recorded.
- Turning the setting off restores manual control without restarting the app.
- Auto-play respects the same terminal conditions as manual play.

## Verification

- Run a round with auto-play off and on.
- Observe both boundary cases and a round reset.
- Record any deliberate difference from the C auto-play behavior.

## Dependencies

BRK-028 and BRK-012.

## Risks and decisions

Resolve the dead-clamp choice before implementation. Do not add a new AI model
to solve a boundary bug.

## Stop conditions / escalation

Stop if auto-play changes score, brick, or round rules rather than only paddle
control.
