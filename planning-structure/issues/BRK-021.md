## Objective

Provide a bounded name-entry interaction that can be reused by save slots and
high-score recording.

## Value / context

Names are currently handled by a manual scancode scan and delay. The rewrite
needs a clear input boundary before persistence and score screens depend on it.

## In scope

- Start/stop behavior for name entry.
- Accepted text, maximum length, deletion, and confirmation.
- Empty-name behavior.
- Visible current name and help/limit feedback.
- The chosen keyboard/text-input semantics.

## Out of scope

- Writing a save file.
- Sorting or hashing scores.
- Localization or a general text editor.

## Requirements

- Input cannot exceed the documented maximum name length.
- Backspace removes the most recent accepted character safely.
- Enter/Return completes the interaction and exposes the result to the caller.
- The empty-name policy is explicit and consistent across save and score flows.
- The chosen uppercase/text-input behavior is recorded if it differs from the
  original.

## Acceptance criteria

- A user can enter, delete, and confirm a name in the visible keyboard screen.
- Overlong input is rejected without corrupting the stored string.
- Empty input follows the documented policy.
- The input loop returns a result rather than modifying unrelated screen state
  behind the caller's back.

## Verification

- Test normal characters, maximum length, over-limit input, deletion, empty
  confirmation, and cancellation if supported.
- Repeat entry after leaving and re-entering the screen.

## Dependencies

BRK-014 and BRK-017.

## Risks and decisions

Resolve whether to reproduce the old uppercase/default and hand-rolled-repeat
behavior or use SDL text-input events. Do not add score/save side effects here.

## Stop conditions / escalation

Stop if the input behavior cannot be tested independently of persistence or if
the requested character rules expand into localization work.
